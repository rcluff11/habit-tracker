## Acceptance criteria
Each line names how it is checked.

1. **Old agent pipeline removed.** Given the branch head, when you read `CLAUDE.md` "Working with the agents" and list `.claude/agents/`, then `.claude/agents/` holds exactly the 9 agents in `AGENTS.md` § 1 (analyst, architect, backend-engineer, data-engineer, devops, frontend-engineer, review-coordinator, sdet, ux-designer), and `CLAUDE.md` no longer assigns work to a "Design agent", "Frontend agent", "Backend agent" or "Reviewer". Check: `ls .claude/agents` and `grep -nE "Design agent|Backend agent|Frontend agent|\*\*Reviewer" CLAUDE.md` returns nothing.
2. **Notch-specific agent skills added.** Given `.claude/skills/`, then each of the 9 agents has a matching `notch-*` skill (the review coordinator included), and each agent file in `.claude/agents/` loads its skill. Check: `ls .claude/skills` lists `notch-analyst`, `notch-architect`, `notch-backend`, `notch-data-engineer`, `notch-devops`, `notch-frontend`, `notch-review-coordinator`, `notch-sdet`, `notch-ux`; grep each agent file for its skill name.
3. **Hooks and CI wired.** Given a fresh clone, when `sh scripts/setup-hooks.sh` runs, then `git config core.hooksPath` prints `.githooks`; a commit message without `T-NNN` is rejected by `.githooks/commit-msg`; and `.github/workflows/checks.yml` runs `scripts/ci-checks.sh` on pull requests. Check: `sh scripts/test/test-commit-msg.sh`, `sh scripts/test/test-ci-wiring.sh` and `sh scripts/test/test-task-ledgers.sh` pass. Whether `main` requires the check (`ADOPTING.md` § 5) is a GitHub setting the owner confirms by hand and records in the activity log.
4. **Tier 1 docs landed with unanimous sign-off.** Given `/docs/`, then every Tier 1 doc in `docs/README.md` exists, contains no unreplaced starter placeholder (text starting `[insert `), and the review artifact under `docs/reviews/chore-adopt-agentic-mastery/` records PASS or PASS WITH ITEMS from all 9 agents, with no open BLOCKER. Check: `grep -rn "\[insert " docs/` returns nothing; the final review artifact lists 9 sign-offs.
5. **All app test suites passing.** Given PocketBase running locally on the branch head, when `npm run test:api`, `npm run test:stats`, `npm run test:reminders` and `npm run build` run, then all four exit 0, and the reviewer attack scripts `node scripts/t3-energy-attack.mjs`, `node scripts/t4-nudges-attack.mjs` and `node scripts/t5-courses-attack.mjs` exit 0. The output is recorded in the review artifact. No app code changes on this branch, so a failure is recorded as a finding and a follow-up task, not fixed here.
6. **Security findings triaged.** Given the Architect's findings in the review artifact, then every finding has a severity (BLOCKER / WARNING / SUGGESTION) and one outcome: fixed on this branch (process files only), accepted with a reason, or moved to a named follow-up task `T-NNN` that exists in `tasks/`. Check: no finding in the artifact lacks one of those three outcomes.

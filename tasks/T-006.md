# T-006 — Make destructive actions safe and stop saves from failing silently

## Description
**Priority 5 of 9 (the UX Designer asks for UX-1 and UX-2 before the phase 2 deploy).** Deleting a block or a category takes one tap, has no confirmation, and silently rewrites past weeks (block delete removes every repeat, its tasks, their check-offs and block-task targets). Several saves fail with no message, and a double tap creates duplicates. This task adds confirmations with counts, warnings on history-changing edits, honest error messages with a retry, and in-flight guards.

- **Planned branch:** `fix/destructive-action-safety` (created when this task moves to in-review).
- **Stakeholder / DRI:** rcluff11.
- **Closes:** UX-1 = DATA-6 = SCOPE-5 (block delete); UX-2 = DATA-7 (category delete, UI and server); UX-13 (task delete wording); UX-14 (history-changing edits); UX-15 (unsaved work, palette replace); UX-10 (error messages, BLOCKER); UX-12 = FE-4 (silent failures); FE-5 (double-submit); FE-6 (reload race); FE-11 (401 shown as a network error); FE-14 (failed load looks like data loss); SEC-12 (logout push failure).
- **Owner decision needed first (SCOPE-5):** either amend CLAUDE.md principle 3 to list task and block deletion as accepted, warned exceptions, or keep the principle and add the warnings. The default in this plan is the second: add the warnings and leave the principle text alone.
- **Review scope (`AGENTS.md` § 5):** full cycle, all 9 agents (user-facing behaviour change; the category-delete server rule changes a documented contract).

## Acceptance criteria
1. **Block delete confirms with counts.** Given a repeating block with a check-off task and past completions, when the user taps Delete, then a confirmation names the block and states the number of repeats, check-off tasks, check-offs and monthly targets that go, and that past weeks' points go down. Cancel leaves everything unchanged. The count logic lives in `src/lib/stats.js` (a `blockDeleteImpact`, like `courseDeleteImpact`) with `test:stats` cases.
2. **Category delete is protected.** The UI confirms with counts (tasks, blocks, rewards, targets). The server refuses deleting a category used by a reward or plan target (or applies the behaviour chosen in review), and a cross-user delete returns 404. Check: `test:api` case pinning PocketBase 0.41's non-cascade behaviour plus the new rule.
3. **Task delete says what history goes** ("Its 60 check-offs (240 points) will be removed from past weeks."), using `completionIndex.byTask`. Check: `test:stats` for the count helper.
4. **History-changing edits warn.** Editing a block's repeat, date or weekday, a habit's start/end/type, or a reward's target/kind on a record with past completions shows an inline note "This also changes past weeks' totals." Check: helper in `src/lib` with a `test:stats` case; manual check at 375px in light and dark recorded in the PR.
5. **Unsaved work.** `Modal` takes an `isDirty` prop: when dirty, a backdrop tap does nothing and Esc asks "Discard changes?". Choosing a preset over a Custom palette confirms.
6. **Errors are honest and actionable.** One `friendlyError(err, action)` helper in `src/lib` (Node-tested). Every write path that failed silently (`Calendar.jsx` block ✓, `Progress.jsx` submit/delete/claim reward, `Settings.jsx` category and user-field writes, `BlockEditor.jsx` delete) shows inline `role="alert"` text and leaves no unhandled rejection. The App banner has "Try again" calling `reload()`. A failed first load renders an error state, not empty views. A 401 clears the auth store and shows log-in (`pb.afterSend`). A failed `disablePush` on logout shows a warning.
7. **No duplicates.** Save buttons in `TaskEditor`, `BlockEditor`, `addCategory` and the Calendar ✓ have an in-flight guard and `disabled`/`aria-busy`. `reload()` ignores stale results (sequence number) so a write made during a reload is not lost.
8. **Tests.** Logic is moved into `src/lib` and covered by `test:stats`; UI-only parts state the manual check in the PR and reference the e2e task (T-012, SDET-4). Manual QA alone is not accepted. All suites green.
9. `docs/ux.md` (destructive-action table) and `contracts.md` (category delete) are updated in the same PR.

## Out of scope

- Contrast and touch-target fixes: T-007.

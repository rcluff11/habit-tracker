# T-009 — Security headers, notification-tap check, and security ADRs

## Description
**Priority 6 of 9 (FE-1 is a deploy blocker that needs only an ADR).** The site sends no security headers and no CSP while the auth token sits in `localStorage`; a notification tap can navigate to any origin; and three standing decisions (token storage, the sender's superuser login, a hand-built VM) cross agent redlines without a recorded decision. This task adds the headers in Report-Only first, the service-worker check, self-hosted fonts so the CSP stays tight, a production-build guard, and the ADRs.

- **Planned branch:** `chore/security-headers-and-adrs` (created when this task moves to in-review).
- **Stakeholder / DRI:** rcluff11 (accepts each ADR as area DRI and as leadership).
- **Closes:** FE-2 = SEC-3 = OPS-8 (headers/CSP); SEC-4 = FE-3 (service worker same-origin); FE-1 (ADR 0002, token storage); SEC-2 = OPS-7 (ADR, interim sender superuser with operational controls); OPS-11 (ADR, hand-built VM accepted with checked-in unit files); FE-13 (self-hosted fonts); SEC-8 (production build fails without an `https://` `VITE_PB_URL`).
- **Review scope (`AGENTS.md` § 5):** all 9 agents (ADRs live in `/docs/decisions/`, and headers are a user-visible config change). Architect + DevOps own the policy and headers; Frontend verifies.

## Acceptance criteria
1. **Headers.** `netlify.toml` has the `[[headers]] for = "/*"` block from `round-3-devops.md` OPS-8 with the real PocketBase host, CSP as `Content-Security-Policy-Report-Only`, and `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` enforced. HSTS is added only if `curl -sI` shows Netlify doesn't send it. Check: `curl -sI` on the deploy preview shows each header.
2. **CSP is clean before it is enforced.** After at least a week of Report-Only with no violations in Safari Web Inspector (iOS Home Screen app) and `chrome://inspect` (Android), the header is switched to `Content-Security-Policy` in a follow-up commit referencing this task. The PR records which devices were checked.
3. **Fonts self-hosted.** Fraunces and DM Sans woff2 subsets under `public/fonts/` with `@font-face` (`font-display: swap`), the Google Fonts `@import` removed, and the CSP's Google hosts dropped. Licence (SIL OFL 1.1) noted in the PR. No new npm dependency.
4. **Notification taps stay on the site.** `public/sw.js` resolves `data.url` against its origin and falls back to `/` for any other origin or a parse error. The URL logic is a pure function tested in Node: `https://evil.example/` → `/`, `//evil.example` → `/`, `javascript:alert(1)` → `/`, `/#tasks` → `/#tasks`. `contracts.md` § 5 and § 12 I-6 say "enforced".
5. **Production build guard.** `vite build` in production mode fails when `VITE_PB_URL` is unset or not `https://`. Check: a run with it unset exits non-zero; the normal Netlify build still passes.
6. **ADRs written and accepted by the owner.** In `docs/decisions/`: ADR 0002 "Auth token in localStorage" (FE-1 compensating controls: CSP, no third-party script, explicit token lifetime, refresh and 401 handling); ADR 0003 "Push sender authenticates as a dedicated superuser (interim)" (SEC-2 option 2 with the OPS-7 controls, and a revisit trigger); ADR 0004 "VM is configured by hand, with unit files checked in" (OPS-11). Each records the owner's acceptance in their exact words. Check: the files and the acceptance lines.
7. All suites green; `contracts.md` § 7/§ 8 and `architecture.md` § 6 updated in the same PR.

## Out of scope
- A least-privilege `services` auth collection for the sender (SEC-2 option 1): T-012, revisit per ADR 0003.
- An HTTP-only cookie session (FE-1 alternative): rejected in ADR 0002 unless rich user content is added.
- Checking in the unit files themselves: T-010 (they come from the VM).

## Risks / dependencies
- A CSP mistake breaks the installed app; Report-Only first is the mitigation.
- The PocketBase host is hard-coded in `netlify.toml`; T-008 or a later task can add a CI check that it matches `VITE_PB_URL`.

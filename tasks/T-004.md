# T-004 — Harden the push sender and push subscriptions

## Description
**Priority 2 of 9 (deploy blocker; exploitable in production today).** Any self-registered account can make the VM send HTTPS POSTs to any host, including loopback and internal addresses, by saving a fake push subscription (SEC-1 = BE-1, confirmed by the SDET live probe). One endpoint that never answers stops every user's reminders until someone restarts the sender (BE-2). This task closes both, makes one bad subscription unable to stop the tick for everyone, and adds the sender heartbeat so a hung sender is noticed.

- **Planned branch:** `fix/push-sender-hardening` (created when this task moves to in-review).
- **Stakeholder / DRI:** rcluff11.
- **Source:** `docs/reviews/chore-adopt-agentic-mastery/final.md` (fix plan), findings below.
- **Closes:** SEC-1 = BE-1 = SDET probe; BE-2 (= T-9, part of SEC-6); BE-3; BE-4; BE-5; BE-6; BE-10 = DATA-2 = SEC-6 (sender side); BE-15; BE-16; SDET-5; SDET-11; OPS-4 step 2 (sender heartbeat); OPS-15.
- **Review scope (`AGENTS.md` § 5):** full cycle, all 9 agents. It changes a documented contract (`push_subscriptions` create/update gains a 400 for non-push hosts; `contracts.md` § 1.2, § 2.3, § 4, § 11, § 12 I-7) and is security-sensitive. Regression-safety check required.

## Acceptance criteria
1. **Allowlist on create and update.** Given PocketBase running with this branch's hooks, when a user creates or updates a `push_subscriptions` record whose `subscription.endpoint` is any of `https://127.0.0.1/x`, `https://169.254.169.254/`, `https://localhost:8090/x`, `https://10.0.0.1/x`, `https://[::1]/x`, `https://user:pass@fcm.googleapis.com/x`, `https://fcm.googleapis.com.attacker.example/x`, `https://fcm.googleapis.com:8443/x`, or an endpoint longer than 1000 characters, then the request returns 400. One endpoint each on FCM, Apple (`web.push.apple.com`), Mozilla and WNS hosts returns 200. Check: new `test:api` cases, shown failing before the fix and passing after (`round-3-sdet.md` table).
2. **The allowlist is a regex, not `new URL()`** (goja may lack `URL`), and the same pattern pair lives in `push/sender.mjs` with a "keep in sync" comment on both sides. Check: code review; `contracts.md` § 11 lists the pair.
3. **Sender skips non-allowlisted rows.** Given a stored subscription whose endpoint fails the allowlist, when a tick runs, then `sendNotification` is never called for it and the skip is logged by subscription id only. Check: new `sender-test` (or `reminders-test`) case with an injected fake `sendNotification` that records calls.
4. **Send timeout and per-host breaker.** Given a fake push endpoint that never resolves, when a tick sends to it and then to a second subscription, then the second send happens within the timeout plus a margin (fake timers, no real waiting). After 3 consecutive timeouts or 5xx for one host, that host is skipped for 5 minutes and logged once. Check: `sender-test` cases. The `timeout` option name is confirmed against the installed `web-push` README and cited in the PR.
5. **One subscription can't stop the tick.** Given subscription 1 throws while its messages are built, then subscription 2 still gets its message. Check: `sender-test`.
6. **Expired-subscription delete is honest.** Given a 410 and a failing delete, then the log records a failure, not "Removed", and no further messages are sent to that subscription in the same tick. Check: `sender-test`.
7. **Re-auth after 401/403, and a tick watchdog.** Given a 401 from PocketBase, then the auth store is cleared and the next tick logs in again. Given a tick that runs longer than 50 s, then the process logs `tick_timeout` and exits non-zero (systemd restarts it). Check: `sender-test` cases.
8. **Scoped queries.** Given a user with no subscription, then none of their blocks, tasks or completions are fetched; messages for subscribed users are unchanged. `blocks` and `tasks` are fetched with a `fields:` list. Check: t4 § 9 extended with a spy or row count.
9. **Logs.** One JSON line per event with a per-tick id and `sub.id`; push-service bodies are truncated to 200 characters; no endpoint, key, email or message text is logged. Check: code review plus a `sender-test` assertion on one log line.
10. **Heartbeat.** When `HEARTBEAT_URL` is set in `push/.env`, the sender pings it after each completed tick (`/fail` on a failed tick) with a 5 s timeout that never blocks the loop. `contracts.md` § 8 lists `HEARTBEAT_URL` as a secret. Check: `sender-test` with a fake fetch.
11. **Safe test push.** `npm run push:test -- --user <id>` sends only to that user's devices. Check: `sender-test`.
12. **Fixture and docs.** `scripts/api-test.mjs` uses `https://fcm.googleapis.com/fcm/send/test-<stamp>` (SDET-11). `contracts.md`, `api.md`, `architecture.md` § 7 and `runbooks/push-reminders-stopped.md` are updated in the same PR. All suites green: `build`, `test:stats`, `test:reminders`, `test:api`, t3, t4, t5.

## Out of scope
- A least-privilege service account for the sender (SEC-2 option 1). The ADR for the interim superuser is T-009.
- Per-user record caps (SEC-6 hooks side, DATA-12): T-012.
- Deploying. The owner deploys once at the end of the phase (T-011).

## Risks / dependencies
- The push-host list must be confirmed against each browser vendor's current documentation before merging; a missing host silently stops reminders for that browser's users.
- Rows saved before the fix stay in the table. The sender skips them; whether to delete them is decided in review.
- Needs PocketBase running locally for `test:api` and t4 § 9.

# T-007 — Fix contrast, touch targets and screen-reader gaps

## Description
**Priority 7 of 9.** The app fails WCAG 2.2 AA in both themes: primary buttons, theme tokens, text on user-chosen block colours and the main check control fail contrast; most controls are below 44×44 px on phones; three inputs have no label; auth fields have no `autocomplete`; selected state is colour-only. Each of these is a pre-existing UX redline breach that blocks the next PR touching its flow. Most fixes are token or CSS changes with no visual redesign.

- **Planned branch:** `fix/accessibility-contrast` (created when this task moves to in-review).
- **Stakeholder / DRI:** rcluff11.
- **Closes:** UX-3 = FE-15 (primary buttons); UX-4 (`textOn`); UX-5 (theme tokens); UX-6 (task check ring); UX-7 (touch targets); UX-8 (labels); UX-9 (autocomplete); UX-11 (selected state); UX-16 (toggle semantics); UX-17 = FE-22 (calendar block semantics); UX-18 (reduced motion); UX-19 (dark-mode token gaps, dark `theme-color`); UX-20 (input borders); UX-22 (view changes announced).
- **Review scope (`AGENTS.md` § 5):** Frontend + UX + Test Engineer (UI polish plus a tested `textOn` change), Coordinator drives. If `docs/ux.md` changes, all 9 for that file.

## Acceptance criteria
1. **Contrast, measured.** Every pair in the UX review's contrast table meets 4.5:1 for text and 3:1 for large text and UI parts, in light and dark. The PR includes the before/after ratios from the same WCAG formula. Candidate values from `round-2-ux.md` are the default.
2. **`textOn` uses WCAG contrast.** `textOn(color)` returns whichever of `#fff` and `#000` has the higher WCAG contrast. Check: a `test:stats` case asserting every colour in every built-in `PALETTES` entry gives ≥ 4.5:1 with its chosen text colour. Done blocks don't drop below that (no whole-block opacity).
3. **Check control.** The task check ring is ≥ 3:1 against its surface for every palette colour; the ✓ colour comes from `textOn`.
4. **Touch targets.** At ≤ 760 px, `.icon-btn`, `.btn-sm`, `button.chip`, `.seg button`, `.swatch`, `.btn` are ≥ 44×44 px; `.task-check` and `.cal-check` have a ≥ 44 px hit area that doesn't overlap the edit button. Check: manual check at 375 px recorded in the PR with measurements from devtools.
5. **Names and state.** The three placeholder-only inputs have accessible names; auth fields have `autoComplete` (`name`, `email`, `new-password`/`current-password`); filter chips, palette presets and swatches expose `aria-pressed` and a non-colour cue; the task toggle has a stable name with real state; Calendar blocks are a real `<button>` with the ✓ as a sibling, Space works, and ↻ is announced as text.
6. **Motion and theme.** One global `prefers-reduced-motion` rule; dark values for `--accent-grad`, `--sun`, `--sky`; a dark `theme-color` meta; ring gradient stops use tokens.
7. **View changes announced.** On a view change, `document.title` becomes "<label> · Notch" and focus moves to the view's `<h1>`.
8. All suites green; `docs/ux.md` updated if a token or rule changes.
